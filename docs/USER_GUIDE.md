# PatchBridge 使用指南

## 1. 启动

双击项目根目录的 `start.bat`。浏览器会打开：

```text
http://127.0.0.1:8765/
```

如果端口被占用，程序会自动尝试 8766、8767…并打开实际端口。

## 2. 新建工程

进入“工程” → “新建工程”，编辑 profile：

```ini
# PatchBridge profile v1
name: 我的项目
root: C:\Users\me\code\my-project
mode: exclude

[rules]
.git/
node_modules/
dist/
*.min.js
*.log
!dist/keep.js
```

- `root` 必须是绝对路径。
- `mode: exclude` 表示默认全部包含，规则命中则排除。
- `mode: include` 表示只有规则命中的文件才包含。
- `!` 是重新纳入。
- 保存后，如果根目录不存在/不可访问，卡片会显示红色“不可用”，不能打开或打包。

## 3. 选择文件并打包

1. 打开工程。
2. 左侧搜索路径，勾选文件，或勾选目录级联选中子文件。
3. 文件树下方会列出被自动排除的**二进制文件路径**；点击路径可复制绝对路径，方便确认是否真的为二进制。
4. 右侧输入需求，越具体越好：期望行为、边界条件、验收标准。
5. 点击“生成打包文本”。

结果区会显示：

- 文件数、总大小、粗略 token 数；
- **完整文件路径**；
- **复制完整文本**按钮；
- **复制文件路径**按钮；
- 下载文本文件、预览文本。

两种方式任选其一：

### 方式 A：复制完整文本

点击“复制完整文本”，打开 Web AI 对话框，粘贴。

### 方式 B：复制文件路径

点击“复制文件路径”，在资源管理器中打开该路径，把 `bundle.txt` 上传给支持文件的 AI；
或双击打开后复制文件内容。

打包文本中包含固定提示词，要求 AI 按以下格式回答：

```markdown
## 修改说明
...
## Commit 建议
...
## 文件补丁
### 相对路径
```diff
...
```
```

## 4. 粘贴 AI 回答

进入会话审阅页，把 AI 输出的**全部内容**粘贴到“粘贴 AI 的完整回答”文本框中，点击解析。

程序会自动：

- 找修改说明、commit 建议；
- 找每个文件的 unified diff；
- 识别 `a/`、`b/`、绝对路径、缺少语言标记、缺少标题等情况；
- 显示 warning；
- 归一化路径并判断原始 `-pN`。

解析结果不会自动应用，必须由你审阅。

## 5. 审阅补丁

每个文件卡片显示：

- 路径、新增/删除行数；
- `hash 一致` / `hash 变化` / `文件缺失` / `新增文件`；
- `可应用` / `冲突` / `不支持`；
- `范围内` / `工程外` / `被 profile 排除`；
- 可展开的带行号 diff。

可以：

- 点击“单文件 dry-run”或“全部 dry-run”；
- 点击“编辑补丁”，修改后保存，工具会重新解析并重新检查；
- 修改 commit 建议；
- 只勾选一部分文件进行部分应用。

### 补丁冲突定位与编辑器

当补丁上下文与当前文件不匹配时，卡片会显示具体原因，并提供“打开补丁编辑器”。

编辑器上半部分是**冲突定位**：

- 左侧是补丁的上下文/删除/新增行；
- 右侧是当前文件对应行；
- 第一处不匹配会高亮；
- 如果只是缩进不同，会显示补丁和文件各自的前导空格数量；
- 显示 hunk 头、补丁行号和当前文件行号。

下半部分是带行号的补丁编辑器。保存后会重新解析并重新 dry-run；可以按 Tab 插入两个空格。

如果冲突是纯缩进差异，可以点击 **“一键对齐缩进”**：

- 按 hunk 计算统一偏移（例如整体少 2 个空格）；
- 对齐上下文/删除行，并同步平移新增行（可取消“同时平移新增行”）；
- 只有在最终 dry-run 能通过时才填入编辑器；
- 不会自动保存，检查后仍需点击“保存并重新检查”；
- 支持“撤销对齐”。

如果同一 hunk 内不同行需要不同偏移、内容本身不同、或 Tab/空格混用，工具会拒绝自动对齐，保留手工修改方式。

### 模糊应用与 AI 修正请求

dry-run 的顺序是自动的，不需要额外勾选：

1. **严格引擎**：上下文精确匹配；
2. **自动对齐缩进**：只处理整段统一少/多空格的情况；
3. **mpatch 模糊匹配**：在临时副本中按相似度定位 hunk，不会把真实工程目录交给 mpatch 写入。

如果 mpatch 成功，补丁卡片显示 `mpatch 模糊`，下方展示的是副本 `git diff` 生成的最终补丁；
应用时仍会用严格引擎再校验一次。如果 mpatch 也失败：

- 卡片显示 `mpatch 未命中` 和 `待 AI 修正`；
- 展开“修正请求内容”，复制给 Web AI，让它重新生成补丁；
- 小文件（默认 ≤ 16 KB）附完整当前文件；大文件附失败位置附近 ±30 行；
- 修正请求不会修改原始补丁，也不会自动应用。

手动编辑补丁仍然保留，但通常不需要再逐行改空格。mpatch 未安装或不可用时，会跳过第 3 步，
直接给出修正请求。

打开历史详情时的自动预览只计算状态，不落盘 mpatch 报告，也不会把已归档会话解压；只有显式
点击“dry-run”或应用补丁时才会保存报告。

### hash 变化

如果文件在打包后被外部修改：

1. 卡片显示“hash 变化”；
2. 直接应用会被拒绝；
3. 点击应用时弹出确认框，逐项勾选确认后才能继续；
4. 如果补丁上下文已经对不上，仍然会显示冲突并拒绝。

### 应用

点击“应用选中补丁”：

1. 后端重新做一次 dry-run；
2. 校验路径范围、git 仓库、hash 确认；
3. 合并选中补丁（模糊成功的文件使用 mpatch 产物，否则使用原补丁），写备份清单和 journal；
4. 事务式写入；失败整体回滚；
5. 记录 apply 事件。

第一次应用后，本会话的补丁和 commit 文本会锁定。未应用的文件仍可继续应用；如果要改补丁，
使用“重新载入”创建新会话。

## 6. 撤回

有未撤回应用时，审阅页显示“撤回最近一次应用”。

- 严格 LIFO：先撤回最后一次应用；
- 撤回前比较当前文件与“应用后”hash；
- 如果文件被外部改过，会弹出确认；
- 修改过的文件按备份恢复，新增文件删除；
- 归档会话撤回时会先自动解压。

撤回操作记录在事件时间线中。

## 7. 历史会话

“历史会话”支持：

- 按工程、状态、日期过滤；
- 按标题/工程/ID 搜索；
- 查看需求、文件快照、bundle、回答原文、解析结果、补丁、事件；
- 导出 Markdown 文档；
- 导出 `.patch`（可在干净副本上 `git apply`）；
- 与当前磁盘比较“应用后”差异；
- 重新载入（生成新会话，原会话保留）；
- 归档为 zip；
- 删除（不会还原磁盘文件）。

如果手动删除了 `data/sessions/<id>/`，索引会检测到不一致并自动重建，也可以点击“重建”。

## 8. 归档

- 手动归档：会话目录变成 `data/sessions/<id>.zip`，列表仍可见，详情可读。
- 有未撤回应用时会提示“撤回时将先解压”。
- 自动归档默认关闭；在设置中开启并指定天数后，只归档没有未撤回 apply 且状态为
  `reverted` / `abandoned` 的旧会话。

## 9. 设置

- 大文件阈值（MB）
- 自动归档开关/天数
- 提示词模板路径
- mpatch 可执行文件路径（留空自动查找 PATH 和 `C:\portable_apps\bin\mpatch.exe`）
- mpatch 模糊相似度阈值（默认 0.7）
- mpatch 超时秒数（默认 60）
- AI 修正请求：整文件附加上限（默认 16384 字节）、失败位置上下文行数（默认 30）
- 备份保留天数
- 最大扫描文件数
- 单次打包大小上限

提示词模板留空使用内置模板；支持 `{{PROJECT_NAME}}`、`{{FILE_COUNT}}`、
`{{TOTAL_BYTES}}` 等占位符。

## 10. 常见问题

**提示“工程根目录不可访问”**

检查 profile 的 `root` 是否是绝对路径、目录是否存在、当前用户是否有读权限。

**解析不到补丁**

确认 AI 回答中是 unified diff（包含 `---`、`+++`、`@@`）。可以手工编辑补丁后再应用。
如果回答完全不是 diff，工具不会猜测。

**提示“补丁上下文与当前文件不匹配”**

文件在打包后发生了变化，或 AI 给的行号/上下文不正确。工具会自动尝试缩进对齐和 mpatch；
仍失败时，复制卡片中的“AI 修正请求”回 Web AI 重新生成，或使用补丁编辑器手工修正。

**设置页显示“mpatch 不可用”**

安装 mpatch 1.8+，把可执行文件放到 PATH 或 `C:\portable_apps\bin\mpatch.exe`，也可以在设置中填
绝对路径。没有 mpatch 不影响严格引擎、缩进对齐、应用和撤回，只是少一层模糊匹配。

**提示“不是 git 仓库”**

在工程根目录执行：

```bash
git init
```

**应用失败后**

工具会按备份回滚。如果进程被强制终止，下次启动会根据 journal 自动回滚未完成的 apply。

**想重做已经应用的补丁**

不要直接改补丁。点击“重新载入”生成新会话，重新校验 hash 后再操作。
